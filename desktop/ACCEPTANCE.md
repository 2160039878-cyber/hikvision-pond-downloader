## 已通过

- 根目录与桌面核心共 11 组自动化测试：跨月拆分、跨设备计划、录像覆盖合并、合成录像串行处理、缺失凭据隔离、取消、鉴权阻断、损坏文件、复制哈希、非覆盖、长文件名、QSV 校验失败后的软件回退、IPC 桥接静态检查及旧 API 回归。
- 真实录像机：DS-8832N-R8(C)，固件 V4.82.100 build 240606。SDK 读取数字通道配置发现 28 个已配置通道，28 个名称读取成功；在线状态 27 在线、1 离线。
- 指定的 10 秒录像区间：27 个通道有录像、1 个通道无录像，无查询失败。27 段下载、转码、目标大小及 SHA256 校验全部通过；无录像片段正确跳过，整体状态为部分完成。
- 另行对 27 段进行 SHA256 比对及全片解码，全部通过。独立窗口播放器逐段加载 27/27 成功。
- 原有 16 个鱼池短片水印全部对应；其余样片中有两个球机未见可读位置水印，未宣称已独立确认它们的物理安装位置。现场图像只保存在本地验收目录。
- Electron 窗口、首次添加弹窗、设置页面正常，检查时无浏览器控制台错误；Windows safeStorage 加解密往返成功。
- 真实桌面操作链：通过页面添加设备并发现摄像头、选择时间、预览、提交、取消、恢复、播放；勾选密码保存后磁盘只出现密文，执行忘记密码后密文记录清空。
- 打包后的“开始.exe”实际启动成功，打开独立窗口并创建空白用户数据；启动环境 PATH 已去除 Node.js 与外部 FFmpeg，仅保留 Windows 系统工具。此项是在现有电脑上执行，不是干净 Windows 验收。

## 修复的实际问题

- 旧 FFmpeg 对超过传统路径长度的目标临时文件报文件不存在。复制临时文件改为目标目录下的短随机文件名，并增加长文件名回归。
- QSV 退出码成功但输出校验失败时，原来未进入软件回退；现在对输出校验失败也执行软件编码。
- Windows PowerShell 的 JSON 组件在本机初始化异常。SDK 工作进程采用固定字段 Base64 标准输入、受限输出协议，不依赖该组件，也不把密码放入命令行。
